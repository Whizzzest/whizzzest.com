# 社媒聚合页方案（`/social/` · `/en/social/`）

> 2026-10-14 业主拍板立项。业主报「看看有没有 whizzzest.com/social，没有就参考做一页，风格和整站契合，入口放页脚最右边、提示 see more」。
> 本文件为实施依据；实施过程与线上验收记入 [上线记录.md](./上线记录.md)，任务声明见 [任务看板.md](./任务看板.md)。

## 一、背景与现状

| 核查项 | 结论 |
| --- | --- |
| `https://whizzzest.com/social` | **404**（实测，落站内 404 页）——全站没有社媒聚合页 |
| 社媒现有形态 | 仅页脚一排图标：`.footer-social`（[footer.html](../src/partials/footer.html)），数据源 `site.footer.socials` |
| 中文页脚渠道 | 分享本站(二维码组)、哔哩哔哩、微信视频号(二维码)、微信公众号(二维码)、抖音、小红书 |
| 英文页脚渠道 | 分享本站(二维码组)、X、Discord、Facebook、Instagram、YouTube（**与中文页脚完全不同的两套**） |
| 图标 | `src/data/social-icons.json`（11 个内联 SVG，`fill="currentColor"`，随主题变色），由 build.js 注入 `s.svg` |
| 二维码弹窗 | 全站常驻灯箱（`src/partials/footer.html` + `src/assets/js/main.js`），任意页面写 `data-qr`（单码）/ `data-qr-list`（分享二维码组）即可复用 → **新页面零新 JS** |
| 静态页成本 | [加功能检查单.md](./加功能检查单.md)：`src/pages/` 建目录 + `src/data/` 同名 JSON **自动发现、零登记**；sitemap / hreflang / sw 预缓存 / `?v=` 指纹全自动 |

参考件 `components/social-cards/` 来自**业主个人站 nathanpenny.fun**（README 内链指向 `pages/contact.html`、`styles/style.css`），是 Shadow DOM + 自带 CSS 变量的独立 web component。**结论：只作设计参考，不入库、不引入**——本仓是「零依赖构建 + 单一设计系统（`src/assets/css/style.css`）」，引入会多出第四套样式来源，并牵出 SW 预缓存、`?v=` 指纹与许可归属的额外工作。

## 二、业主拍板决策（2026-10-14）

1. **入口文案**：中文「查看更多 ›」／英文「See more ›」（各自本地化，与站内 `t.common.readMore` 风格一致）；位置 = 页脚 `.footer-social` 图标行**最右端**。
2. **页面内容**：渠道卡墙 + 扫码关注区 + 联系与分享区（全量，不做最简版）。
3. **中英页均列全平台**：`/social/` 也列 X/Discord/Facebook/Instagram/YouTube，`/en/social/` 也列哔哩哔哩/视频号/公众号/抖音/小红书；分组顺序按当前语言**母语平台优先**（zh：国内平台 → 海外平台；en：Global → China）。
4. `components/social-cards/` 只作参考，不接入。

### 二轮修订（同日，业主看线上首版后拍板）

5. **不要「扫码关注」区**：公众号/视频号二维码不再内联铺开（仍可从渠道卡点击开全站灯箱，与页脚同一条路径）。
6. **不要大图 hero**：页头改用站内既有 `.hero-flat` 浅色文字头，「简约一点」。
7. **英文页同样保留企业咨询**：联系与分享三格中英一致，「不然就不对称了」。
8. **卡片稍微缩小**：图标/字号/内边距/圆角/栅格间距整体收一档。

## 四、数据结构（单一事实源）

新增 `src/data/social-channels.json`：

```jsonc
{
  "groups": [ { "key": "cn", "zh": "国内平台", "en": "China platforms" }, … ],
  "channelOrder": { "zh": ["cn", "global"], "en": ["global", "cn"] },
  "channels": [
    { "icon": "bilibili", "group": "cn",
      "zh": { "name": "哔哩哔哩", "desc": "…" },
      "en": { "name": "Bilibili", "desc": "…" } }
  ]
}
```

- **只写文案与分组**：`href` / `qr` / `qrList` 一律按 `icon` 从**两个 locale 的** `site.footer.socials` 并集解析（**本语言条目优先、缺失的用另一语言兜底**）→ 链接永不重复维护；未知 icon、两侧都查不到链接 → **构建期报错**（照 `site.footer.socials` 既有校验口径）。
- build.js 新增 `resolveSocialChannels()`（约 45 行）：页面数据里声明 `"socialChannels": true` 即启用——为渠道注入 `svg` + 链接字段 + 三态布尔，并按语言产出 `data.socialGroups`（母语平台优先的分组数组）与 `data.share`（分享本站条目，供分享灯箱入口）。模板条件只支持单路径真值，分组必须在构建期算好。
- **在线咨询 href 跨 locale 解析**：企业微信客服链接只在 zh 站页脚配置（`site.footer.onlineSupport`），英文站页脚没有；但英文聚合页要保留这张卡（业主拍板「不然就不对称了」）→ 页面数据声明 `"contactSupport": true`，build.js 取**任一 locale** 的 `onlineSupport.href` 注入 `data.supportHref`（label/desc 由页面数据按语言给），两边都查不到即构建失败。**英文页脚未改**（仍只列邮箱）。
- 页面文案（页头/区块标题/CTA/联系区）放 `src/data/social.json` + `src/data/en/social.json`（英文文件必须含 `meta.title/description`，否则构建失败——既有约定）。

## 五、页脚入口

- [footer.html](../src/partials/footer.html) 里，链接放在 `.footer-social` **之后、同级**（同一 `.footer-legal` flex 行的最右端），href 取 `site.footer.socialMoreHref`（`/social/` 与 `/en/social/`，per-locale 数据，符合站内「href 落数据」惯例），文案取新增 `t.footer.socialMore`。
- **为什么不塞进 `.footer-social` 内部**：图标行内会成为 `a:last-child`，抢走 [style.css](../src/assets/css/style.css) 里那条给小红书横排字标放大一档的规则（`21px`）。放在同级后该规则零影响——本地实测小红书字标仍为 21px。样式 `.footer-social-more`（12px 胶囊、hairline 描边、hover 转焰色）落在 `.footer-social` 规则之后。
